# 验证协议

验证层用于检查解析后的房源数据是否与原始来源页面一致。

## 抽样

每次抓取后的默认抽样规模：

- 贝壳：20-50 条房源
- Wellcee：20-50 条房源

抽样应覆盖：

- 新出现的房源
- 解析置信度较低的房源
- 缺少核心字段的房源
- 疑似重复房源候选

## 验证材料

每条抽样房源应提供：

- 数据源名称
- 原站 URL
- 已解析字段
- 原始页面路径
- 页面截图路径，如果有
- 解析置信度
- 当前验证状态
- 备注字段

阶段 1 当前会生成两份 CSV：

- `data/validation/phase1_validation_sample.csv`：严格过滤后进入人工验证的样本。
- `data/validation/phase1_filter_candidates.csv`：所有候选房源及程序排除原因，用于检查过滤是否过严或误伤。

## 字段检查

| 字段 | 检查问题 |
| --- | --- |
| `title` | 解析出的标题是否与来源页面一致？ |
| `rent_price` | 解析出的租金是否与来源页面一致？ |
| `area_sqm` | 解析出的面积是否与来源页面一致？ |
| `location` | 行政区、小区、地址等位置字段是否与来源页面一致？ |
| `images` | 保存的图片 URL 是否对应当前房源？ |
| `availability` | 房源是否仍可访问，还是已经下架？ |

## 状态值

字段级状态：

- `correct`：正确
- `incorrect`：错误
- `missing`：缺失
- `not_applicable`：不适用
- `unknown`：未知

整体状态：

- `pass`：通过
- `fail`：失败
- `needs_review`：需要复查
- `down`：已下架或不可访问

## 指标

按数据源和抓取批次统计：

- 标题正确率
- 租金正确率
- 面积正确率
- 位置正确率
- 图片正确率
- URL 有效率
- 解析失败率
- 重复候选准确率

## 进入分析层的门槛

不要在以下条件满足前开始严肃分析：

- 标准化房源可以追溯到原始页面。
- 核心字段正确率达到可接受水平。
- 常见解析失败原因已经明确。
- 随机抽样验证流程可以重复执行。
- 验证结果可以按房源 ID 和数据源保存。
